# Bugfix 058: Persist user errors in session

## Problem
Errors sent to the user (e.g., the fallback "Sorry, I encountered an unexpected error" message in English) are currently not being persisted in the `messages/sessions` mechanism. This causes a gap in the session history and makes debugging and user context recovery difficult.

## Solution
Ensure that any error message dispatched to the user (such as those generated by the fallback `_create_fallback_response` path) is recorded properly in the active session's JSON log, maintaining an accurate audit trail of exactly what the user saw.

## Status
**Fixed** (2026-09-27, `fix(bugfix-058)`). Every message dispatched to the user, and the user
message it answers, must appear in the session — success replies already did, but every
error/fallback path returned text without ever storing it. `_persist_turn` (moved out of
`_finalize_response`) is now the single place that stores a turn, used uniformly by every OpenAI-
call error and every pending-approval (MCP/reminder) success-or-failure path. See PR for this
branch for the full diff and added tests.
