# Contract C9: Full-payload fidelity — fixture manifest + assertion helper

**Feature 069** | [plan.md](../plan.md) · [research.md](../research.md) R2 · FR-069-020,
FR-069-022, SC-004

> User, verbatim: *"In all scenarios that actually create a ledger event at the end - assert
> that ALL the details that we given/extracted in the initial msg made it to the persisted
> event. THIS IS CRITICAL, and (I think but perhaps I am wrong) not trivial to do."*

## Principle

Every acceptance scenario that ends in a persisted `LedgerEvent` must prove **bidirectionally**:

1. **No silent drop** — every field present in the source message/image/document appears in
   the persisted event.
2. **No hallucination** — every non-null non-provenance field in the persisted event traces
   back to the source (or to the resolved Morning client name).

A subset / "contains" assertion is **NOT** sufficient (FR-069-022).

## Per-fixture ground-truth manifest

Each `הסכם`/`בנק` fixture ships a committed sibling manifest:

```text

  agreement_ambiguous.txt           agreement_ambiguous.manifest.json       # US5  — typed הסכם, 1 / 2+ partial
  agreement_photo_multi.png         agreement_photo_multi.manifest.json     # US9  — photographed multi-component הסכם
  agreement_doc_multi.docx          agreement_doc_multi.manifest.json       # US10 — docx multi-component הסכם
  deposit_zero_matches.png          deposit_zero_matches.manifest.json      # US7a — בנק slip, 0 Morning matches
  deposit_one_partial.png           deposit_one_partial.manifest.json       # US7b — בנק slip, 1 partial match
  deposit_two_plus.png              deposit_two_plus.manifest.json          # US7c — בנק slip, 2+ partial matches
  deposit_exact_match.png           deposit_exact_match.manifest.json       # US7d — בנק slip, exact Morning match (no question, no new client)
```

For a `הסכם` fixture (text, photo, **or `docx`**), `expected_event` lists
`source_type: "הסכם"`, the `event_subtype`, the agreement date, `payer_name` where present,
and — critically for US9/US10 — **every fee component as its own manifest entry** (a list
under `components`, each `{kind: "fixed"|"percent", value, description}`). An agreement
manifest with fewer than ~3 distinct components makes the drop-detection assertion weak;
`agreement_photo_multi` and `agreement_doc_multi` each carry a fixed retainer + a success
percentage + a per-hearing fee at minimum. `agreement_id` is **not** manifested — it is
generated by the ledgerer, never sourced.

Manifest shape:

```json
{
  "source_kind": "image" | "text" | "document",
  "expected_event": {
    "source_type": "בנק",
    "event_subtype": "הפקדה",
    "amount": "6200",
    "txn_date": "2026-08-14",
    "description": "...",
    "bank_number": "12",
    "bank_branch": "645",
    "bank_account": "418302",
    "reference": null,
    "payer_name": "רונית בר"
    /* every field the fixture actually contains; resolved client_name handled separately */
  },
  "client_resolution": {
    "scenario": "exact_match" | "one_partial_then_pick" | "two_plus_then_pick" | "zero_matches_then_new" | "store_anyway",
    "morning_name_after_resolution": "רונית בר-און",   /* the exact Morning name expected in client_name */
    "expects_marker_in_description": false               /* true only for store_anyway */

}
```

**Fixtures are deliberately detail-rich** (`user-stories.md`): every fixture carries amount +
date + full banking triplet + reference + a name (for `בנק`), or ≥3 fee components + date +
`payer_name` (for `הסכם`) — so the assertion actually exercises drop detection.

## Assertion helper — `assert_event_matches_manifest(event, manifest)`

Lives in a `tests/billed/` / `tests/expensive/` shared helper module (not a fixture, not
mocking anything). Written in the **Acceptance phase**, not earlier — it is test code for the
billed/expensive tier (METHODOLOGY §VI).

```
PROVENANCE_IGNORE = {
    "event_id", "event_datetime", "captured_at", "session_id", "message_id",
    "schema_version", "reference_hint", "agreement_id", "component_id",
    "_linked_document",
}
```

1. `expected = manifest["expected_event"]` plus
   `client_name = manifest["client_resolution"]["morning_name_after_resolution"]`.
2. **Forward (no drop)**: for every key in `expected`, `event[key] == expected[key]`
   (string-normalized compare — trim, collapse whitespace; dates compared as the event
   stores them). A `null` in `expected` means the event's value must also be null/absent.
3. **Backward (no hallucination)**: for every key on the persisted `event` with a non-null
   value and not in `PROVENANCE_IGNORE`: the key is in `expected`, OR the key is
   `client_name` (step 4), OR the key is `description` (step 5). Any other populated field
   ⇒ **fail** ("unexplained field X = ...").
4. `event["client_name"] == client_name` (the exact resolved Morning name).
5. If `expects_marker_in_description`: `"[לקוח לא אומת במורנינג]" in event["description"]`
   AND `event["client_name"] == <operator-stated name from the fixture>` (overrides step 4 —
   store-anyway keeps the stated name, not a Morning name).
   Else: `description` may be empty or a faithful summary containing no invented specifics
   (assert it does **not** contain the marker phrase).

`schema_version` is in `PROVENANCE_IGNORE` and is **never asserted on** for any value
(CLAUDE.md rule) — it is ignored purely so the backward check does not flag it as an
unexplained field.

## Two-hop assertion for media sources (US7 incl. 7d, US9 images; US10 `docx`)

- **Hop 1 — extraction fidelity**: the extractor's `analyze_media()` output
  (`ledger_events[0]` for images / `document_analysis` + `fields` for `docx`, plus
  `extracted_text`) contains every field in the slip/page/document manifest. Catches
  OCR/vision loss (images) before the detour. For US9/US10 this is where "the model read
  all 3 fee components off the source" is proven.
- **Hop 2 — persistence fidelity**: the persisted `LedgerEvent` matches Hop 1's extracted
  values (not just the manifest) — proves the synthetic-turn stash + multi-turn detour +
  post-turn recognition call lost nothing the extractor had. For US9/US10 this is where "no
  fee component was dropped while resolving the client" is proven. For US7d this proves the
  silent exact-match path persisted the full banking payload with no question asked.

A single-hop check would not distinguish "vision dropped the branch number / a fee
component" from "the resolution detour dropped it" — both are real risks; the contract
requires telling them apart.
